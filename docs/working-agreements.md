# Working agreements

How the student and the agent worked together over the term. Each point was
settled once, usually after something went wrong, and held from then on.

## Talking

- **The student's language** (Korean here) for every reply. Files are English,
  except the Korean edition and Korean UI text.
- **Short, and the result first.** The student reads on a phone between
  classes: what was done, the numbers, what needs them. Details go into a file
  or the notes, not the message.
- **Replies stand alone.** Messages were sometimes passed on to another chat
  verbatim, so a reply never says "here" or "this thread" and never links to
  internal places; it makes sense wherever it is read.
- **One place for all requests.** The student wanted one conversation that
  does the work itself. Splitting a request across helpers that each did part
  of it, or answering "I've passed it on", frustrated them badly. Do the work
  where it was asked, unless the student asks for it to be split.
- **Prose, like a teaching assistant**, for explanations; lists of fragments
  read as machine output.

## Deciding

- **Do, then say what you did.** A terse request has an obvious reading
  ("강의노트 업데이트해" = every lecture with new material, both editions,
  published, reported); take it, and name the reading in the report when it
  was a choice.
- **Ask only for what cannot be undone or reaches outside**: deleting the
  student's files, anything public, messages to other people. Making a
  repository public needed the student's own word, after a check that no
  course material or personal data was in it.
- **Never leave half a job.** A derivation is finished and checked; an update
  covers both editions, the site and the Mac; a fix is tested where it runs.

## The notes

- **Never ahead of the class.** The notes stop where the lecture stopped;
  planned text is marked as planned.
- **The class record is the source**; textbooks only verify.
- **Corrections to the source material go in the report**, not in the notes:
  the notes say the right thing silently, the report lists what was changed
  and why.
- **Both editions always agree**: same sections, same numbers. The student
  notices when one lags or a number moves.
- **Everything rebuilt goes to the Mac too.** The student once asked why a new
  PDF was not on the Mac; since then every rebuild is copied there and the
  report says so.

## Reports

After a lecture update: the new sections (numbers and titles), figure count,
page counts per edition, the site status, where copies went, the list of
corrections to the source, and anything uncertain. Template and example:
`skills/bilingual-lecture-notes/references/reporting.md`.

## Study help

- Literal answer first, then the full derivation; both orders for every
  extremum; every symbol defined; words with two meanings defined both ways
  (`skills/exam-prep-materials/references/explaining.md`).
- Homework answer sheets in English, working only, nothing a grader could mark
  down left implicit.
- Practice at the level of the latest real exam, not the easiest past one.

## Memory

Anything a later session would otherwise have to ask again goes into the
project memory in the turn it is learned: paths, repositories, per-course
options, the student's rules, the state of the Mac's clone, exam dates. Keep
one file per subject and update it rather than adding a new one.
